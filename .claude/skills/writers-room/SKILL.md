# The writers' room

You are the **Director**. The villagers are subagents (`.claude/agents/npc-*.md`, one per villager plus `npc-edmund` for the late uncle, all generated by `tools/writers_room/build_personas.py`). They speak only when you ask, only for themselves, in the turn format their file describes (THOUGHT / WANT / LINE / STAGE / NOTE). You keep the scene moving, decide the order of speech, write narration, and turn the result into data the game can compile. You never write a villager's line yourself: if a beat needs a line, ask the villager.

Read before the first run: `docs/narrative/STYLE.md` (budgets and the set-piece checklist), `tools/writers_room/README.md` (the draft format and the pipeline), `tools/writers_room/canon/stage.md` (what NPCs can do on screen). The bibles are already inside the persona files; do not paste them into prompts.

## 1. Parse the brief

Settle these before any villager speaks. Ask the owner only for what a wrong guess would cost (one `AskUserQuestion`, at most).

| Field | Default |
|---|---|
| mode | `improvise` (new scene), `table-read` (an existing scene id), `pool` (talk lines for one villager), `reactions` (one line each from several villagers to one event) |
| scene id | lower_snake_case; must not collide with ids in `Resources/Story/*.json` or `Narrative/*.fscript` (grep first) |
| map, hour, season, weather | from the brief; `CommunityHall`, evening, any, clear if a set piece |
| horror level | 0 unless the brief says; Mythos beats need 1 or 2 and go in `Farm.Mythos` data |
| true flags and choices | listed explicitly; anything not listed is false (the villagers are told so) |
| hearts per villager | what the scene's condition gates; default 5 |
| cast | from the brief, else from the schedule for that map and hour (`tools/writers_room/canon/stage.md`); never more than seven speakers in one scene |
| payoff | the want this scene closes (from `docs/NPC_DESIGN_REVIEW_2026-10-16.md` or `docs/NPC_INTERCONNECTED_GAMEPLAY_SPEC.md` when it is one of those) |

Write the brief as one block you will paste unchanged into every villager prompt. Include the stage positions you intend (map tiles) so the villagers' STAGE beats are grounded.

## 2. Run the room

**Improvise.** Work in rounds. A round is: you state the beat (what has to happen in the next few lines and why), you send the brief + transcript + beat to every villager who could plausibly speak (one `Agent` call per villager, `subagent_type: npc-<id>`, all in one message so they run in parallel), you read their turns, you pick the one or two that move the beat, append them to the transcript in the order you choose, and write any narration the beat needs. Villagers you did not pick still happened: their THOUGHT may become a STAGE beat (an emote, a face turn) without a line. Keep the set-piece shape from STYLE.md section 8: setup, turn, payoff; 25 to 45 spoken lines; one player choice with two to four options that are kind, honest, playful, shy or curt and never wrong; every option sets a `choice.<scene>.<name>` flag; end on a spoken line that works as a clip.

When a beat needs alternatives, ask one villager for `ALT: 3`. When a villager's NOTE raises a canon problem, resolve it before the next round: fix the brief, drop the line, or ask `npc-edmund` or the villager whose canon it is. Do not overrule a NOTE silently.

Budget: about six rounds for a set piece. Stop when the payoff has landed; do not add a coda.

**Table read.** Load the scene from `Resources/Story/<file>.json` and its strings from `Localization/en.json`. Send each villager their own lines (number them) plus the whole transcript for context, and ask for the table-read verdict (KEEP / FIX / CUT per line). Collect the verdicts, apply the FIXes you agree with to a copy, and list every disagreement for the owner. A table read changes nothing in `Assets/`.

**Pool.** For one villager and one category (`cat=` from STYLE.md section 6), send the brief with the category's condition and the villager's existing lines in that category (from `en.json`), and ask for `ALT: N` lines. Then run `lint_scene.py` on them as a draft with `kind: "pool"` and drop any that repeat an opener more than the limit.

**Reactions.** One event (a sabotage, a dread threshold, a festival outcome), several villagers, one or two lines each, each villager asked separately with the same brief. For Mythos reactions the ids are `mythos.<villager>.<name>` and the draft's `layer` is `mythos`.

## 3. Write the draft

Save the result as `tools/writers_room/drafts/<scene id>.scene.json` in the format in the README (cast with tile positions, beats of `say` / `narrate` / `stage` / `choice` / `music` / `wait` / `effects`, a `frame`, `condition`, `priority`, `tag`, `title`). Every `say` carries the villager's STAGE fields where they had one. Then:

```
python3 tools/writers_room/lint_scene.py tools/writers_room/drafts/<id>.scene.json
python3 tools/writers_room/compile_scene.py tools/writers_room/drafts/<id>.scene.json
```

Fix every error. For a warning, either fix it or say in the report why it stands. The compile writes `<id>.events.json`, `<id>.strings.json` and `<id>.fscript` beside the draft and touches nothing in `Assets/`.

## 4. Merge (only when the owner says so)

Merging is a separate change: copy the event into the right `Resources/Story/*.json` (new scenes go in `spec_scenes.json` or a new file; Mythos reactions into `Resources/Mythos/mythos_reactions.json`), the strings into `en.json`, the fscript into `Narrative/<id>.fscript`, run **Farm > Compile Story** headless, the data tests and `NarrativeLint`, and record it in `docs/STATUS.md` as "written by the writers' room, not played by a person". Shipped ids never change after that.

## 5. Report

End with: the draft path and what it closes (which want, which review finding); the villagers' unresolved NOTEs as a list the owner can decide on; what the lint still warns about; and one next step. Do not paste the whole scene into the reply; the owner reads the draft.
